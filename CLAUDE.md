# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Это **не запускаемое приложение**. Это распространяемый **навык (skill) для Hermes/Claude**, который
превращает ИИ-ассистента в read-only старшего руководителя отдела продаж и CRM-аналитика для
**Bitrix24**. Конечный продукт — это `SKILL.md` вместе с его `references/`, `scripts/` и `examples/`.
Пользователи устанавливают его так:

```bash
hermes skills install https://raw.githubusercontent.com/laserhall/sales-director-crm-analyst-for-bitrix24/main/SKILL.md
```

Бо́льшая часть «разработки» здесь — это редактирование текста (инструкций навыка и справочных
плейбуков), а не кода. Два Python-скрипта — это тонкие пробники без зависимостей, которые проверяют
подключение к Bitrix24.

## Архитектура

В репозитории три согласованных слоя; понимать, как они ссылаются друг на друга, важнее, чем
содержимое любого отдельного файла:

1. **`SKILL.md`** — точка входа и контракт. Его YAML-фронтматтер (`name`, `description`,
   `version`, `tags`) — это то, что читает реестр навыков. Тело файла задаёт персону ассистента, шесть
   режимов анализа (одна сделка, диалог Открытых линий, зависшие сделки, эффективность менеджера,
   здоровье воронки, выигрыш/проигрыш), фиксированные **форматы вывода** для каждого режима, правила
   безопасности и финальный чек-лист проверки. Раздел «workflow links» ссылается на каждый файл в
   `references/`.

2. **`references/*.md`** — база знаний, загружаемая по запросу. `bitrix24-readonly-workflows.md` —
   канонический источник того, *какие REST-методы Bitrix24 разрешены* и как их вызывать/пагинировать;
   остальные файлы — рубрики оценки и плейбуки (SLA, оценка качества диалога, фреймворк анализа сделки,
   плейбуки по follow-up, безопасность данных и т. д.). Когда меняешь разрешённый метод или формат
   вывода в `SKILL.md`, держи эти файлы синхронными.

3. **`scripts/*.py`** — исполняемые read-only пробники Bitrix24 (только стандартная библиотека, без
   зависимостей). Оба скрипта обеспечивают безопасность на уровне кода: они держат жёстко заданный
   allowlist `READ_ONLY_METHODS`, а хелпер `endpoint()` *выбрасывает исключение* на любой метод, которого
   в нём нет, поэтому методы записи нельзя вызвать даже по ошибке. Ошибки проходят через `safe_error()`,
   который редактирует (скрывает) webhook URL перед выводом.
   - `bitrix24_smoke_check.py` — проверяет подключение и печатает сводку возможностей (булевы значения
     того, какие read-методы доступны). Никогда не печатает webhook URL.
   - `analyze_deal_readonly.py` — пробует одну сделку: поля сделки, число активностей, связанный чат
     Открытых линий и небольшую страницу сообщений. Печатает счётчики/ID, но никогда не печатает сырой
     текст сообщений.

`examples/` содержит **анонимизированные** примеры входов/выходов (JSON сделки, JSON диалога Открытых
линий, два примера отчётов). Используй их как образец формата и никогда не заменяй реальными данными
CRM.

## Ключевые инварианты (не нарушать)

Эти правила — весь смысл навыка. Любое изменение должно их сохранять:

- **Read-only по умолчанию.** Только методы `get`/`list`/`search`/history. Никогда не добавляй `add`,
  `update`, `delete`, `set`, `send`, `message.add`, `notify`, `task.add` или методы комментариев таймлайна
  в allowlist скрипта и не рекомендуй их без явного подтверждения пользователя.
- **Гигиена секретов.** `BITRIX24_WEBHOOK_URL` — это секрет. Никогда не печатай, не логируй и не
  коммить его; всегда направляй ошибки через хелпер-редактор при изменении кода скриптов.
- **Двусторонняя согласованность.** Список разрешённых методов и форматы вывода присутствуют и в
  `SKILL.md`, и в `references/bitrix24-readonly-workflows.md` — обновляй их вместе.

## Команды

Здесь нет шага сборки, манифеста пакета или набора тестов. Скрипты используют только стандартную
библиотеку Python (Python 3, `from __future__ import annotations`).

```bash
# Разовая локальная настройка (.env в .gitignore; никогда не коммить его)
cp .env.example .env
# затем отредактируй .env и задай BITRIX24_WEBHOOK_URL

# Загрузи окружение и запусти проверку подключения / возможностей
set -a; source .env; set +a
python3 scripts/bitrix24_smoke_check.py

# Пробник одной сделки (read-only)
set -a; source .env; set +a
python3 scripts/analyze_deal_readonly.py --deal-id 12345
```

Коды возврата: smoke check возвращает `0` при полном успехе, `1` при частичной неудаче, `2` если
переменная окружения с webhook не задана; пробник сделки возвращает `0`/`1`/`2` аналогично. Линтеры и
CI не настроены.

## Соглашения

- Документация **двуязычна**: отвечай на языке пользователя (английский или русский). README содержит
  русский раздел; держи параллельный контент синхронным при редактировании пользовательской
  документации.
- Повышай `version:` во фронтматтере `SKILL.md` при значимых изменениях навыка.
- Скрипты должны оставаться без зависимостей и сохранять свой allowlist `READ_ONLY_METHODS` + редактирование
  (скрытие) URL.
- `.gitignore` намеренно исключает форматы данных, которые могли бы утечь как экспорты CRM (`*.csv`,
  `*.xlsx`, `*.jsonl`, `exports/`, `dumps/`, `reports/private/`, `attachments/`, `*.pdf`) — сохраняй это.
